# Collision Engine

## Overview

Collision diagnostics are generated by the reusable collision framework and consumed by layout optimization and validation scoring.

The engine is diagnostic-first and does not aggressively reposition geometry.

## Supported Collision Classes

- label-label
- label-tick
- tick-tick
- label-boundary
- boundary-overflow
- ring-ring
- cross-ring interference
- text-overflow
- curved-baseline-overflow

## Detection Principles

- angular gap analysis with circular wrap-safe delta computation
- radial proximity checks
- label arc-width estimation based on text length and radius
- ring separation and cross-ring near-miss counting

## Resolution Philosophy

Resolution is optional and conservative:

- preserve mathematical value mapping
- preserve plugin-level geometry intent
- prioritize readability and manufacturability diagnostics

## Outputs

Every collision issue emits structured diagnostics:

- severity
- type
- message
- involved IDs

These diagnostics feed:

- validation warnings
- engineering health scores
- optional UI overlay status
